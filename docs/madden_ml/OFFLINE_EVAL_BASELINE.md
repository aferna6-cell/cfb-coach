# Offline evaluation baseline — 2026-11-06

Generated by `python -m cfb_coach ml heldout-eval --db <read-only backup> --out <dir outside ~/.cfb-coach>`
on the 2026-11-06 backup (PR #93 labels). Only aggregate numbers are included; no opponent
names or play-by-play rows. Re-running on the same backup reproduces these numbers (fixed seed).

## How to read this

- **Section 1** asks "if we already know which play was actually run, can a model forecast how
  it turns out?" Each model is refit on earlier games only and scored on the next unseen game.
  A coin flip has log loss 0.693; the training base rate is the bar to beat.
- **Section 3** describes what the live coach did. It cannot say whether ML calls better plays
  than the heuristic: every live choice was deterministic, so we never observe what the other
  policy's play would have produced.

## Headline findings

1. The experimental shrinkage model is the only model that beats the base rate on *success*
   (log loss 0.6765 vs 0.6850; game-clustered 95% interval of the difference −0.013 to −0.004;
   AUC 0.56). The edge is small and comes from CPU games (516 of 599 test plays). On the 83
   human-game plays and on the 91 per-snap-verified plays it shows no ranking skill (AUC ≈ 0.5).
2. Down/distance tables predict *3rd/4th-down conversion* clearly better than the base rate
   (log loss 0.651 vs 0.698, n = 117). Nothing beats the base rate on explosives or turnovers.
3. Opponent run/pass on our defensive snaps (192 observed plays, 7 human opponents, one game
   each) is not yet predictable: every model — league situation rates, the opponent's own
   history, league → style → individual pooling — scores about the same as a 50/50 guess
   (log loss 0.69–0.73), and no difference is statistically separated. Directionally, the
   opponent's own history hurts during his first 5 plays and helps after 15. A leakage-free
   GBT/MLP check on raw features (`scripts/madden_ml/opponent_gbt_nn_experiment.py`) was also
   inconclusive (LOOO log loss 0.683 / 0.701; chronological only 74 plays in 3 games).
4. Live reliability is good: 1.2% heuristic fallbacks (all timeouts), p95 latency 96 ms,
   p99 153 ms (1.2% of decisions over the 150 ms budget), no final pick outside the applied book.
5. ML and the heuristic agreed on only 6.3% of decisions, and no decision logged a usable
   randomisation probability, so "is ML smarter than the heuristic?" is not answerable from
   existing logs. A prospective randomised comparison is required (see
   `PRIORITY2_HELDOUT_EVAL_PLAN.md`).

## Caveats

- Only plays with a verified execution are scored; recommendations are never treated as executed plays.
- `base_rate` is constant within a test game, so its pooled AUC only reflects drift between folds; read it as 0.5.
- In `exclude_opponent`, every CPU game shares one opponent identity, so CPU test games have no eligible training games and only human games are scored.
- The experimental model is scored with unknown coverage and no heuristic bonus (not reconstructable offline).
- Touchdowns recorded without yardage have unknown explosive labels and are excluded from that target.
- Opponent run/pass comes from the observed concept text; unclassifiable concepts are excluded.
